When every UI is generated by an LLM in real-time, traditional frontend testing breaks down. You can't snapshot test a layout that's different every time. You can't assert specific component choices when the AI decides what to render based on context. The challenge: how do you build confidence that an AI is producing quality visual interfaces — without making the tests as non-deterministic as the system itself?

The answer: **LLM-as-Judge** — using a separate AI to evaluate the primary AI's output against quality rubrics, combined with statistical pass-rate scoring that embraces non-determinism rather than fighting it.

### Architecture

The testing framework operates across three layers, each validating at a different level of abstraction:

* **Layer 1 — Unit Tests:** Validates the deterministic mapping layer that sits between the LLM's raw tool calls and typed UI components. Pure functions, fast, no LLM required.
* **Layer 2 — Structural Validator:** Ensures any AI-generated layout conforms to the SDUI type contract — correct component types, valid props, required fields, logical ordering rules. Deterministic and fast.
* **Layer 3 — LLM-as-Judge Evaluator:** Uses a separate LLM as an independent judge to assess whether the generated layout is a *quality* visual representation of the input data — scoring component appropriateness, layout richness, information extraction, logical flow, completeness, and follow-up action quality.

### Key Achievements
* **LLM-as-Judge Evaluation Pattern:** Implemented the agentic LLM-as-Judge pattern where a separate Claude instance evaluates the primary LLM's output against six quality rubrics — catching regressions in both the system prompt and the model's behavior that deterministic assertions could never surface.
* **Pass-Rate Scoring for Non-Deterministic Output:** Because the same input produces different layouts across runs, each test fixture runs multiple times and a pass rate is tracked. A fixture passes if it meets a configurable threshold — embracing LLM non-determinism rather than fighting it.
* **Fixture-Based Content Archetypes:** Built a catalog of test fixtures representing distinct content patterns (metrics-heavy data, risk assessments, phased timelines, tabular comparisons, scenario analyses) — each with a characteristic reliability profile that reveals how the LLM behaves with different input shapes.
* **CI-Ready Gating:** Unit and structural tests run on every PR in under a second. LLM-as-Judge evaluation runs as a gated nightly job, automatically skipped when no API key is available — keeping the fast path fast while still catching quality drift over time.
