I designed and built, on my own, an agent system that fixes security vulnerabilities at scale. A Wiz scan found more than 5,000 vulnerabilities across the team's repos, far more than anyone could fix one at a time. Instead of working them by hand, I built a system where coding agents do the fixing and developers only review, merge and deploy.

### Campaigns, Grouped by Root Cause

The first step was turning a flat list into something agents can work. I exported every finding and analyzed it with Codex to find the main families: the same vulnerable dependency or the same pattern repeated across many repos. Each family becomes a campaign, so one well-understood fix gets applied everywhere it's needed instead of being rediscovered thousands of times.

### How the Agents Work a Campaign

Each step is a specialized agent skill:

* **Locate the issue** in the affected repo and read the fix Wiz recommends.
* **Run a baseline** first, so the agent knows the state of the build before it changes anything.
* **Apply the fix in an isolated git worktree**, away from anyone's working branch.
* **Run the baseline again.** If the build still passes, the agent opens a pull request with the details of what changed and why.
* **Watch the build after the fix.** If it breaks, or the scan finds new vulnerabilities, the agent keeps working until the build is green.

The agents have opened more than 100 pull requests covering thousands of findings.

### Knowing What Code Can't Fix

Part of the design is recognizing which findings aren't in application code at all. Findings that live in cloud configuration get routed out of the agent pipeline: I worked with the cloud and DevOps teams on Ansible playbooks for those, and the system tracks them as handed off to cloud instead of leaving them in the code queue.

### Its Own State, Synced with Jira

At this volume, Jira alone can't tell you where each finding stands. The system keeps its own state for every finding (fix in progress, pull request open, handed off to cloud) in Azure Blob Storage, and syncs it with Jira whenever an agent works a campaign or someone runs a refresh. A dashboard I built in React, TypeScript and shadcn/ui shows every finding and its status in one place, published to Confluence through the same publisher plugin I built for the AI Task Force.
