# The $3 SEO Audit: How AI Took My Site from 5.5 to 10/10

Right after [launching dimeglio.dev](/blog/building-dimeglio-dev-with-ai), I had that familiar developer itch — the one where you know you forgot something but can't put your finger on it. So on a whim I asked my AI coding assistant to do a full SEO analysis of the site.

Fifteen minutes and roughly $3 in API tokens later, I was staring at a long list of things I'd completely overlooked.

## The Audit

The AI went through every file that matters for SEO: root layout, page components, `next.config.ts`, and searched for sitemaps, robots.txt, canonical URLs, JSON-LD, 404 pages — the works.

Some of it was fine. I'd set up title templates, descriptions, `metadataBase`, OpenGraph cards, a dynamic OG image, semantic HTML with `<main>`, `<article>`, `<time dateTime>`. The bones were there.

But then there was... everything else.

No `sitemap.xml`. No `robots.txt`. Zero JSON-LD structured data — not a single schema. No canonical URLs. No custom 404 page. No RSS feed. No footer at all. No web manifest. No Apple touch icon. And I'd left `maximumScale: 1` in the viewport config, which blocks pinch-to-zoom. That's an accessibility issue, not just an SEO one. Embarrassing.

I'd been so focused on making the site look good and getting the content right that I hadn't thought about discoverability at all. Classic developer move.

## Fixing Everything in One Shot

I told the AI to fix all of it. It laid out a plan, I said "yeah, do it," and it started creating files.

This part went fast. In a single conversation — no context switching, no separate research — it created 8 new files and modified 7 existing ones:

**New files:**
- `app/sitemap.ts` — dynamic XML sitemap that auto-discovers routes and blog posts
- `app/robots.ts` — crawl directives with sitemap reference
- `app/not-found.tsx` — a branded 404 with links back to home and blog
- `app/feed.xml/route.ts` — RSS 2.0 feed from published blog posts
- `app/manifest.ts` — web app manifest
- `app/apple-icon.tsx` — dynamic 180×180 Apple touch icon
- `components/json-ld.tsx` — reusable JSON-LD component with 6 schema factories
- `components/footer.tsx` — site footer with nav, social links, copyright

**Modified files:**
- `app/layout.tsx` — keywords, canonical URL, RSS `<link>`, WebSite JSON-LD, footer component, skip-to-content link, removed that `maximumScale: 1`
- `app/page.tsx` — home metadata + Person JSON-LD
- `app/blog/page.tsx` — canonical + ItemList JSON-LD
- `app/blog/[slug]/page.tsx` — per-post canonical + Article JSON-LD
- `app/experience/page.tsx` — canonical + ProfilePage JSON-LD
- `app/projects/page.tsx` — canonical URL
- `next.config.ts` — security headers (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`)

### The JSON-LD Part

This was the biggest gap and probably the most valuable fix. The AI built a complete structured data system:

```typescript
// components/json-ld.tsx
websiteSchema()      // → every page (via layout)
personSchema()       // → home page
articleSchema(post)  // → each blog post
blogListSchema(posts) // → blog index
profilePageSchema()  // → experience page
breadcrumbSchema()   // → ready for later
```

Each schema follows [schema.org](https://schema.org) specs. The Person schema, for example:

```json
{
  "@type": "Person",
  "name": "Pablo Di Meglio",
  "jobTitle": "Senior Full Stack Engineer",
  "sameAs": [
    "https://www.linkedin.com/in/dimegliopablo/",
    "https://github.com/pdimeglio-dev"
  ],
  "knowsAbout": ["TypeScript", "React", "AI Architecture", ...]
}
```

This is what Google uses for Knowledge Panels and rich results. It's also what AI-powered search engines (Perplexity, Google AI Overviews) pull from when generating summaries about people. Kind of important for a portfolio site.

## What It Cost

I keep thinking about the economics of this. A traditional SEO audit from a consultant runs $500–$2,000, and that's just the audit — implementation is extra. A freelance developer to implement fixes might be another $500–$1,500 over a few days.

This was ~$3 in API tokens and about 15 minutes of my time, most of which was reviewing the plan and approving file changes.

Now, obviously there's a catch. I'm a senior engineer. I knew what good SEO looks like. I could evaluate every suggestion and would have caught bad advice. The AI didn't teach me anything — it just did the tedious work of actually implementing patterns I already knew about but hadn't gotten around to.

That's the part I find most interesting. It wasn't a knowledge problem, it was a time and motivation problem. I *knew* I needed a sitemap. I *knew* I should have JSON-LD. I just hadn't done it because it's boring and I was busy making the site look nice. AI doesn't get bored, doesn't procrastinate, doesn't prioritize the fun stuff over the important stuff.

## Code Snippets for Your Own Site

If you're running a Next.js App Router site and want to do something similar, here are the key patterns:

### Dynamic Sitemap

```typescript
// app/sitemap.ts
export default function sitemap(): MetadataRoute.Sitemap {
  const posts = getBlogPosts();
  return [
    { url: "https://yoursite.com", priority: 1 },
    ...posts.map((post) => ({
      url: `https://yoursite.com/blog/${post.slug}`,
      lastModified: new Date(post.frontmatter.date),
    })),
  ];
}
```

### Reusable JSON-LD Component

```typescript
// components/json-ld.tsx
export function JsonLd({ data }: { data: Record<string, any> }) {
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: JSON.stringify(data) }}
    />
  );
}
```

### Security Headers

```typescript
// next.config.ts
const nextConfig: NextConfig = {
  async headers() {
    return [{
      source: "/(.*)",
      headers: [
        { key: "X-Frame-Options", value: "SAMEORIGIN" },
        { key: "X-Content-Type-Options", value: "nosniff" },
        { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
      ],
    }];
  },
};
```

### Skip-to-Content Link

```tsx
// Root layout, before the header
<a
  href="#main-content"
  className="sr-only focus:not-sr-only focus:fixed focus:z-[100] ..."
>
  Skip to content
</a>
```

## The Pattern

What sticks with me about this whole thing isn't the SEO specifically. It's how the workflow went: I spotted a problem, asked AI to analyze it comprehensively, reviewed its plan, let it execute, and checked the output. Fifteen minutes for something that would have taken me a day or two if I'd done it by hand — not because it's hard, but because there are fifteen separate files to create and update and it's just... a lot of typing.

That's where AI is most useful to me right now. Not the hard problems — the annoying ones.
